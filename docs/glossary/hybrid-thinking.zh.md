# Hybrid Thinking（chat-template 驱动的思考模式融合）

> English: [hybrid-thinking.md](./hybrid-thinking.md)

**Slug:** `hybrid-thinking`
**类别：** alignment
**一句话概括：** 一种后训练食谱——把 long-CoT 推理（"thinking"）和直接回复（"non-thinking"）两种行为融合到同一组权重里，推理时用 chat-template 指令切换，而不是部署两个独立模型。
**首次提出：** [Qwen3 Technical Report (Qwen Team, 2025)](https://arxiv.org/abs/2505.09388)

## 概述

前沿模型常把能力拆成两个 checkpoint：推理调优版（long CoT，慢、贵）和指令调优版（短、快、便宜）。Hybrid Thinking 把两者合到同一个 checkpoint：

- **训练**（Qwen3 四阶段后训练的第 3 阶段，称为 *Thinking Mode Fusion*）：在推理 RL 后的 checkpoint 上继续做 SFT，混合大约 50/50 的 thinking 样本（从推理 RL 模型自身做 rejection sampling，以保质量）和 non-thinking 样本（精选的多领域指令数据）。Chat template 引入 `/think` 和 `/no_think` 指令插在 user/system 消息里，并约定 non-thinking 回复使用空的 `<think></think>` 块。

- **推理**：用户通过在 prompt 中插入 `/think` 或 `/no_think` 切换模式（或在 HuggingFace tokenizer 中设 `enable_thinking=False`）。多轮对话可以交错使用——模型遵从最近一次 flag。Kimi K2.5/2.6 通过 `thinking` 布尔 kwarg 采用类似模式。

- **Thinking budget** 自然涌现：模型一旦能舒服地处理被截断的 thinking 块的回复，你就可以在中途插入一个固定的 stop-thinking 哨兵 token 来打断思考，模型会基于已有的推理直接给出最终答案。这个能力在 Qwen3 中 *没有* 单独训练——是 Thinking Mode Fusion 的免费副产品。

这个模式与 OpenAI 的 reasoning-effort 旋钮和 Anthropic Claude 的 extended-thinking 旋钮思路相近（但不完全相同）——后者也是在单一模型上暴露一个显式推理预算。

## 使用此技术的模型

| 模型               | 变体 / 细节                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Qwen3-32B          | `/think`（默认）vs `/no_think` 指令插在 user/system 消息里；`<think>...</think>` 包住推理块。两种模式的默认采样不同（thinking：T=0.6、top-p=0.95、top-k=20；non-thinking：T=0.7、top-p=0.8、top-k=20、presence_penalty=1.5）。Thinking-budget 控制通过插入哨兵 `"Considering the limited time by the user, I have to give the solution based on the thinking directly now. </think>"`。                                                                                                                                                                         |
| Qwen3-235B-A22B    | 与 Qwen3-32B 同食谱（包括 Thinking Mode Fusion 在内的四阶段 pipeline 在两个旗舰间共享）。235B-A22B 同时是 Strong-to-Weak 蒸馏中两个教师之一（另一个是 32B），把 thinking + non-thinking 行为传给较小的 Qwen3 规模。                                                                                                                                                                                                                                                                                                                                             |
| Qwen3.5-27B        | Chat-template 信封仍是 `<think>...</think>`，但 **`/think` / `/no_think` 软开关被移除**（README："Qwen3.5 does not officially support the soft switch of Qwen3"）。模式切换只剩 API 上的 `chat_template_kwargs={"enable_thinking": False}`（阿里云模型工作室简化为顶层 `enable_thinking` kwarg）。默认 thinking on。两种模式的采样默认值仍然不同（thinking T=1.0 / top-p=0.95；non-thinking T=0.7 / top-p=0.8）。生成融合权重的后训练 pipeline 没有像 Qwen3 那样披露细节。                                                                                      |
| Qwen3.5-35B-A3B    | Chat-template + API 切换与 Qwen3.5-27B 完全相同——只支持 `enable_thinking` API kwarg，不支持 `/think` 软开关。两种模式的采样默认值相同。MoE 骨干不影响运行时模式机制。                                                                                                                                                                                                                                                                                                                                                                                           |
| Qwen3.6-27B        | 与 Qwen3.5 一致的 `enable_thinking` API 切换；软开关**已彻底从 template 移除**——template 里 5 处 `/think` 子串全部出现在 `</think>` 闭标签内（实际 `/think` / `/no_think` 软开关指令数为 0；Qwen3.5 是运行时不响应但模板里还留着字面量）。**新增第三个正交 kwarg `preserve_thinking`**（默认 False）：为 True 时模型在历史轮次的 `<think>...</think>` 块上保留并条件化，而不仅是最近一次 user 消息。厂商论点是这能改善多轮 agent 决策一致性、减少重复推导以节省 token、并提升 KV-cache 利用率。能力是"额外训练"而来，但食谱（继续 SFT？RL？数据规模？）没披露。 |
| Qwen3.6-35B-A3B    | API kwarg 与 Qwen3.6-27B 相同：`enable_thinking` + `preserve_thinking`（无软开关）。Chat template 与 Qwen3.6-27B 字节相同（2 处 `preserve_thinking`，0 处 `/think` 软开关——5 处 `/think` 子串全部是 `</think>` 闭标签的一部分）。多轮 `<think>` 保留规则（滑动窗口？全历史？打 tag？）template 和 README 都没说明。                                                                                                                                                                                                                                             |
| Kimi K2.5          | 原生多模态权重，通过 `thinking` kwarg 切换模式（Instant vs Thinking）。Thinking 模式下发射 `<think>...</think>` 块，内容通过 `reasoning_content` 暴露。                                                                                                                                                                                                                                                                                                                                                                                                         |
| Kimi K2.6          | 与 K2.5 相同的 `thinking` kwarg，增加 `preserve_thinking` kwarg 用于多轮推理保留（匹配 Qwen3.6 / GLM-4.7 行为）。                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| GLM-4.7            | Z.AI 平行实现的 Qwen3.6 风格三模式 hybrid thinking。Chat-template kwargs `enable_thinking`（默认 true；逐轮开关 thinking）和 `clear_thinking`（默认 true；切换历史 `<think>` 块是否保留）。README 明确命名三种模式：**Interleaved Thinking**（GLM-4.5 时引入）、**Preserved Thinking**（GLM-4.7 引入，推荐用于 τ²-Bench / Terminal Bench 2.0）、**Turn-level Thinking**（逐轮 `enable_thinking=false`）。vLLM `--reasoning-parser glm45` 解析 `<think>...</think>` 信封。                                                                                       |
| GLM-5 / GLM-5.1    | 与 GLM-4.7 相同的三模式设计（论文 §3.1）——Interleaved + Preserved + Turn-level Thinking，使用相同的 `enable_thinking` / `clear_thinking` kwargs。GLM-5 论文引用 Claude Opus 4.5 作为 Preserved Thinking 的灵感来源。GLM-5.1 的 chat template 加入更复杂的逐 user 轮次 thinking 出现追踪（`thinking_indices` namespace），用于在 GLM-5.1 后训练refresh 所瞄准的"数百轮 / 数千次工具调用"智能体场景下更准确地重渲染历史 thinking 块。采样默认（默认 reasoning 模式）：`temperature=1.0, top_p=0.95, max_new_tokens=131072`（GLM-5 README HLE 评估脚注）。         |
| Qwen3.8-27B        | 保留 `enable_thinking` 开关，但**模式轴变成三维**：`enable_thinking` × `reasoning_effort`（xhigh / medium / low，新增——见 [reasoning-effort](./reasoning-effort.zh.md)）× `preserve_thinking`。相对 3.6 有两处行为变化：(1) **`preserve_thinking` 默认值从 OFF 翻转为 ON**——模板条件变成 `preserve_thinking is undefined or ... is true`，调用方现在需要显式 opt-*out* 才能不带完整推理历史；(2) 3.6 里把 `<think>`/`</think>` 从历史 content 字符串中切出来的兜底逻辑被删除，历史消息被要求以结构化形式传入。                                                  |
| Qwen3.8-2.4T-A95B  | **本仓库第一个把 non-thinking 直接删掉的模型**：chat template 在 `enable_thinking=false` 时抛出 `'Disabling thinking is not supported.'`。混合思考塌缩为「只有思考」，深度改由 `reasoning_effort` 控制。值得注意的是，基于同一权重的**托管版** Qwen3.8-Max 是支持 non-thinking 的——所以这个限制属于开源发布形态，而非模型本身。`preserve_thinking` 与 27B 一样默认开启。                                                                                                                                                                                        |
| Qwen3.8-Flash-Next | chat template 与 Qwen3.8-27B 逐字节相同，因此完整的三轴接口原样继承（`enable_thinking` × `reasoning_effort` × `preserve_thinking`，后者默认开启）。与 Qwen3.8-2.4T-A95B 不同，它**保留了** non-thinking 模式。                                                                                                                                                                                                                                                                                                                                                  |
| GLM-5.2            | `enable_thinking` 和 `clear_thinking` 从 GLM-5 / 5.1 继承下来，并新增了 `reasoning_effort` 这一轴（见 [推理强度控制](./reasoning-effort.zh.md)）。注意 GLM 与 Qwen 的极性相反：kwarg 是以*清除*行为命名的，所以「保留完整历史」是 `clear_thinking=false` 而不是 `preserve_thinking=true`。默认仍是只保留最近一轮。                                                                                                                                                                                                                                              |
| GLM-5.3-Flash      | **`enable_thinking` 被移除**——模板无条件打开 `<think>` 块，混合思考塌缩为「只有思考」，深度由 `reasoning_effort` 控制。这是本仓库第二个删掉该开关的模型，距 Qwen3.8-2.4T-A95B 仅数周。另外 `clear_thinking` 默认值变为 `false`，即**默认保留完整推理历史**——与 Qwen 在 3.8 代做的默认翻转相同，只是通过极性相反的 kwarg 表达。                                                                                                                                                                                                                                  |
